# ADR-002: Разделение лейаутов и двухуровневая изоляция ролей (RBAC)

## Статус
Accepted

## Дата
2026-08-31

## Контекст
Платформа обслуживает два типа пользователей с кардинально разными сценариями работы:
1. **Студенты**: просмотр каталога, интерактивный плеер уроков, сдача заданий, AI-тьютор, прохождение тестов, сертификаты.
2. **Администраторы**: аналитика воронки, аудит действий, CRUD курсов/модулей/уроков/квизов, триаж студентов и управление когортами.

Смешивание интерфейса администрирования с клиентским UI перегружает DOM, усложняет код страниц и создаёт риски случайной утечки административных функций.

## Решение
Реализовать двухуровневую изоляцию:
1. **Frontend**:
   - Отдельный лейаут AdminLayout с фиксированным сайдбаром, системным статусом и тёмной темой #0a0a0c.
   - Клиентский лейаут с шапкой Navbar, каталогом и учебным кабинетом.
   - Компонент ProtectedRoute с флагом dminOnly для перехвата неавторизованных переходов.
2. **Backend**:
   - Ролевая модель: STUDENT, ADMIN.
   - Все контроллеры /api/v1/admin/** закрыты через @PreAuthorize("hasRole('ADMIN')").
   - Row-Level Security через SecurityUtils.getCurrentUserId().

## Последствия
- Полная визуальная и структурная изоляция клиентского и административного интерфейсов.
- Defense-in-depth: попытки взлома на стороне клиента блокируются на уровне контроллеров бэкенда (403 Forbidden).
