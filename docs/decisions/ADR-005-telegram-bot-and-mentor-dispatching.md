# ADR-005: Telegram Bot Polling Runner и диспетчеризация команд ментора/студента

## Статус
Accepted

## Дата
2026-09-01

## Контекст
Для быстрого реагирования на SOS-сигналы студентов («Не получается / Сложно справляться») и оперативной проверки сданных домашних заданий ментору необходим постоянный мобильный пульт управления.
В условиях Educational MVP (Level 3) и локального запуска бэкенда без публичного белого IP/SSL для входящих Telegram Webhook требовалось выбрать надёжный механизм доставки сообщений.

## Решение
1. **Режим Long-Polling (`TelegramBotPollingRunner`)**:
   - Автоматический запуск фонового демона polling при старте Spring Boot (`app.telegram.polling-enabled=true`).
   - Использование официального HTTP API Telegram `getUpdates` с `timeout=30s` и контролем `offset`.
2. **Диспетчеризация и умный парсинг (`TelegramBotCommandService`)**:
   - Извлечение числовых ID (`#1`, `[1]`, `1`, `<1>`) без `NumberFormatException`.
   - Поддержка русских алиасов (`дз` -> `/hw`, `принять 1` -> `/approve 1`, `отклонить 1 правка` -> `/reject 1 правка`).
   - Изоляция аккаунтов: команды проверки ДЗ и статистики доступны только авторизованному ментору (`TELEGRAM_CHAT_ID`).
   - Авто-связывание аккаунтов студентов через токены глубоких ссылок (`/start LINK_<token>`) и email.
3. **Отказоустойчивость**:
   - Маскирование внутренних ошибок БД и Hibernate при падениях с возвратом понятного сообщения.

## Последствия
- Полная работоспособность бота как в локальном окружении, так и в облачном контейнере (Render / Fly.io) без необходимости настройки обратных вебхуков и проброса портов.
- Мгновенная проверка ДЗ ментором с мобильного устройства в 1 клик.
